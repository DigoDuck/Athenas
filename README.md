# Athenas

Personal study platform (Django + DRF, React + Vite, PostgreSQL). The v1 scope is in
`docs/spec.md`; decisions are in `DECISIONS.md`.

Requirements: Docker Desktop (set to start with Windows), `make`, Python 3 (only for the
use-mode helper, the backup task and the theme script).

## Dev mode

Hot reload, own database and volume (`athenas-dev`).

```bash
make dev-up      # frontend on http://127.0.0.1:5470, API on http://127.0.0.1:8471
make dev-down
make lint        # ruff + eslint, inside containers
make test        # pytest against the dev Postgres
```

## Use mode

Always on, listens on `127.0.0.1:8470` only, own database and volume (`athenas`). It only runs
a clean, tagged commit. From the release with login (D-044) on, the account named in
`DJANGO_SUPERUSER_USERNAME` and `DJANGO_SUPERUSER_PASSWORD` in `.env.use` is created on start;
`make use-init` writes both, and an older `.env.use` needs the two lines added by hand.

```bash
make use-init    # once: creates .env.use with generated secrets (git-ignored)
git checkout v0.1.0
make use-up      # builds and starts with restart: unless-stopped
make use-down
```

Bookmark `http://127.0.0.1:8470`. Containers come back after a reboot as long as Docker
Desktop starts with Windows.

## Backup and restore

The backend exports into a staging folder on `C:`, and an hourly Windows task copies it to the
vault (`DECISIONS.md` D-019, D-028). Set both folders in `.env.use` as absolute paths:
`BACKUP_STAGING` on `C:` and `BACKUP_VAULT`, which must already exist in the vault. Then, once:

```bash
python scripts/backup.py register   # hourly task "Athenas backup"
python scripts/backup.py run        # one run now; check backup.log in the staging folder
```

Restore replaces everything in use mode with one export. Make a fresh export first, and copy
the export folder back from the vault into `BACKUP_STAGING` if it is no longer there:

```bash
docker compose --env-file .env.use exec backend python manage.py backup --force
docker compose --env-file .env.use exec backend python manage.py flush --noinput
docker compose --env-file .env.use exec backend python manage.py loaddata /backup/athenas-YYYYMMDD-HHMMSS/data.json
```

An export made before 2026-10-17 16:38 UTC (content migration 0005) has no `generated_by`, and
loaddata does not run the migration that fills it, so AI text would show as Diogo's. After
restoring one, derive it again from the saved Markdown (safe on any export, `DECISIONS.md` D-039):

```bash
docker compose --env-file .env.use exec backend python manage.py shell -c "from content.models import Content; from content.parser import parse_markdown; [Content.objects.filter(pk=c.pk).update(generated_by=parse_markdown(c.raw_markdown).generated_by) for c in Content.objects.all()]"
```

## Day 28 metric

Prints the blocks of the first month and the reading of `DECISIONS.md` D-010, as Markdown for
the verdict entry (D-038). It only reads. For the verdict, run it on 2026-11-14 or later, from
PowerShell in the use-mode checkout:

```bash
docker compose --env-file .env.use exec -T backend python manage.py day28
```

## Themes generated by Claude

Claude Code builds a whole track from one line with the `athenas-tema` skill (`DECISIONS.md`
D-030). Open Claude Code in this folder and type, for example:

```text
/athenas-tema Docker: rodar meus projetos Django
```

It writes `temas/<slug>/` (git-ignored) from sources it opened, checks it with
`python scripts/theme.py check`, and saves it into use mode with `python scripts/theme.py push`.
A subtopic already in the app is replaced only when its file is named after the folder,
`push temas/<slug> --replace <file>`, and the app's copy is kept beside it as
`<file>.app-<time>.md`.
Cards enter pending and wait for approval in the app. To try it without touching the experiment,
point it at a disposable copy with `--base http://127.0.0.1:8472`.
